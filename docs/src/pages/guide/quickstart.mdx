# Quick start

Requires **scarb ≥ 2.20** (ships `scarb execute`, `scarb prove`, `scarb verify`).

## 1. Validate the bigint math

```sh
cd cairo/lib
scarb test
# 42 passed — 31 arithmetic (256/512/1024/2048 bits, joint-exponentiation edges)
# + 11 verifier: Barrett and mu checks, prime challenge, full Wesolowski
# verification, forgery / negated-output / composite-challenge rejection,
# RSW keystream roundtrip
```

The full verification fits cairo-test's 2^32 gas cap (~1.09B gas with the
hash-to-prime challenge), so the positive *and* forged-negative paths run in
the default test run.

## 2. Run the full verification as an executable (gas off)

```sh
cd ../exec
python3 ../../scripts/write_exec_args.py  # writes vectors/exec_args_{512,2048}.json
scarb execute --arguments-file ../../vectors/exec_args_512.json --print-program-output
# Program output: <instance_hash> <ctx> <poseidon(ct)> <poseidon(pt)>
# [0, 0, 0, 0] means rejection
```

This runs the ~8.49M-step computation with gas disabled — the same path the
prover will consume. It verifies the VDF, then decrypts the ciphertext under
the key derived from `|y|` and `ctx`. The output is not a boolean: the onchain
side recomputes `instance_hash` and `poseidon(ct)` from its stored puzzle and
ciphertext and compares `poseidon(pt)` with the bid commitment, binding the
proof to that exact instance and ciphertext.

## 3. Prove the execution (big machine)

```sh
scarb execute --output=standard --arguments-file ../../vectors/exec_args_512.json
scarb prove --execution-id 1
# -> target/execute/vdf_exec/execution1/proof/proof.json
scarb verify --proof-file target/execute/vdf_exec/execution1/proof/proof.json
```

> **Proving measurements**: the historical 14.8M-step 512-bit program generated
> a proof in ~90s on a 64GB box; verification then hit an ECDSA-segment assertion
> ([stwo-cairo#1733](https://github.com/starkware-libs/stwo-cairo/issues/1733)).
> The current 8.49M-step trace has been executed and tested, but proving
> time, memory use and proof verification have not yet been measured.

## Modulus sizes

`N_LIMBS` in `cairo/lib/src/lib.cairo` selects the domain:

| N_LIMBS | Modulus | Use |
|---|---|---|
| 8 | 512-bit | demo / CI / small boxes |
| 16 | 1024-bit | intermediate benchmark |
| 32 | 2048-bit | production, serious proving machine |
